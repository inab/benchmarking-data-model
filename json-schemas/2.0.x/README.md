# OpenEBench Scientific benchmarking data model 2.0.x, three layers in one

This folder contains the JSON Schema describing the three layers of usage
of the OpenEBench Scientific benchmarking data model.

1. The public layer represents what it is returned by the REST API and
   it is sent to it in order change some property.

2. The disk layer represents what it is stored at the level of MongoDB
   documents distributed over the different collections related to the
   modelled concepts.

3. The changesets and patches layer represents a portable way to describe
   which entries were changed at once in a transaction, and the patches
   of each affected entry describing the differences between the previous
   revision of each entry and the one stored in this transaction.

## Property naming conventions

* When a property name starts with any character which is not an underscore,
  it means it belongs to both the public data model (the one used by the REST API)
  **and** the disk data model (the one used to store entries in MongoDB).

* When a property name starts with an underscore, it means it belongs to
  both the public data model (the one used by the REST API) **and** the disk
  data model (the one used to store entries in MongoDB).

* When a property name starts with two underscores, it means it is (or it
  should be) generated by the REST layer (so it is read only), and it is
  **only** part of the public data model. Changes to those attributes
  should be either ignored or rejected. The property name should also end
  with two underscores.

* When a property name starts with three underscores, it means it is **only**
  part of the on disk data model (the one used to store entries in MongoDB).
  The property name should also end with three underscores.
